# MoonReel — MVP Architecture

> Goal: validate the workflow **niche → AI script → review → produce a video with a recurring character → final render**, using **Meta Muse (muse.ai)** as the provider so AI cost comes out of an existing muse.ai token allowance.

## 1. Overview

```
┌─────────────────────── moonreel-studio (app) ───────────────────────────┐
│                                                                           │
│  Next.js 16 (UI + Server Actions + API)        Worker (Node, pg-boss)     │
│  ├─ Niches      niche templates + config       ├─ script-generate         │
│  ├─ Characters  characters + reference image   ├─ character-reference     │
│  ├─ Projects    create → edit/approve script   ├─ scene-produce           │
│  └─ /api/files  serves local images/videos     └─ project-render (FFmpeg) │
│            │                                          │                   │
│            └────────────► PostgreSQL ◄────────────────┘                   │
│                     (app data + pg-boss queues)                           │
└──────────────────────────────────────┬────────────────────────────────────┘
                                       │ HTTP (OpenAI-compatible)
                          ┌────────────▼─────────────┐
                          │ muse2api (Docker)         │  headless Chromium
                          │ /v1/chat/completions      │  driving muse.ai with
                          │ /v1/images/tasks          │  the account's cookies
                          │ /v1/videos                │
                          └────────────┬─────────────┘
                                       ▼
                                muse.ai (your tokens)
```

| Component | Technology | Why |
|---|---|---|
| Web app | Next.js 16 (App Router, Cache Components), Tailwind 4 | One codebase for UI and backend |
| DB / ORM | PostgreSQL 17 + Drizzle ORM | Schema in TypeScript, no codegen |
| Queue | pg-boss 12 | Runs on the same Postgres: no Redis, no cloud bill |
| Provider | muse2api (self-hosted, MIT) | Free, spends muse.ai tokens |
| Rendering | FFmpeg | Available locally, enough for the MVP |
| File storage | Local disk (`~/.moonreel/storage`) | Swap for S3/R2 later behind `lib/storage.ts` |

Generated files live **outside the repo** on purpose: `next dev` watches the project folder, so writing images, clips or muse2api's `tasks.json` inside it makes the dev server recompile and reload the page in a loop.

## 2. Data model

```
niches 1──* projects *──* characters   (project_characters, ordered: the lead first)
  │             │
  └──*──* characters                    (niche_characters: the default cast)
                │
                1
                │
                * scenes
```

**niches**: the template that drives every script in a channel
- `name`, `description`, `icon` (emoji shown in the UI)
- `scriptInstructions`: niche-specific rules for the AI (structure, hook, CTA, things to avoid…)
- `tone`, `visualStyle` (applied to every scene), `language`
- `sceneCount`, `sceneSeconds` (default 6 scenes × 10 s)
- `defaultAspectRatio` and the default cast (`niche_characters`): preselected when creating a video

**The active niche** is stored in the `moonreel_niche` cookie. On first visit the user must pick a niche; the dashboard, the video list and the new-video form are then scoped to it. **Switch niche** in the sidebar changes it.

**characters**: recurring on-screen characters; a project has a cast of any number of them
- `name`, `appearance` (detailed "character bible"), `personality`
- `referenceImagePath`: canonical reference image (uploaded or generated by Muse)
- `referenceStatus`: `none | generating | ready | failed`

**projects**: one video
- `title`, `topic`, `aspectRatio` (`9:16` | `16:9`), `nicheId`; the cast lives in `project_characters` (`position` 0 is the lead)
- `status`: `scripting → script_ready → producing → rendering → done` (or `failed`)
- `finalVideoPath`, `captionsPath`, `error`

**scenes**: one scene ≈ one Muse clip
- `characterIds`: the cast members on screen, picked by the script (at most 3) and editable per scene. A project with a single character shows it in every scene, whatever this holds.
- `index`, `narration` (spoken line), `visualPrompt`, `camera`
- `status`: `pending → keyframe → video → done` (or `failed`)
- `keyframePath`, `clipPath`, `error`

## 3. Flow

```
[UI] Pick a niche (first visit / Switch niche) ──► cookie moonreel_niche
[UI] Create project (in the active niche) ──► job script-generate
                         │  muse2api chat: prompt = niche + character + topic
                         │  → JSON {title, scenes[]} → zod validation, one repair attempt
                         ▼
                   status = script_ready
[UI] User edits scenes / regenerates the script
[UI] Approve ──► one scene-produce job per scene, status = producing
                         │  1. Keyframe: muse2api image (character reference + scene description + aspect ratio)
                         │  2. Clip: muse2api video (keyframe as first frame + quoted narration)
                         │  3. Download into storage
                         ▼
             last scene done ──► job project-render (singleton per project)
                         │  FFmpeg: normalise to 720×1280 / 1280×720, 30 fps, concatenate
                         │  + .srt captions (soft subtitles)
                         ▼
                   status = done → watch / download the MP4
                         │
                         ▼
             job project-posts (singleton per project, also from "Rewrite captions")
                         │  one chat turn (AI Gateway or Muse) → per-platform captions
                         │  chapter times read from the .srt cue starts
                         ▼
                   projects.posts (jsonb), posts_status = ready
                         │  first time only: projects.thumbnail spec (headline, photo prompt, fallback scene)
                         ▼
             job project-thumbnail (singleton per project, also from the thumbnail form)
                         │  1. Background, only when missing: Muse image framed for the niche's template,
                         │     or a scene keyframe (chosen, or fallback when Muse declines)
                         │  2. Satori lays out the template overlay (fonts in assets/fonts),
                         │     resvg rasterises it, sharp composites it over the background → JPEG
                         ▼
                   thumbnail.jpg, thumbnail_status = ready
```

Thumbnail templates live in `src/lib/pipeline/thumbnail.ts` (rendering) and `src/components/thumbnail-preview.tsx` (the CSS mock-up in niche settings); keep the two in step. Headlines are broken into lines before rendering, from per-font glyph widths, so the layout does not depend on Satori's wrapping. The fonts (Anton, Oswald, Montserrat; SIL Open Font License, see `assets/fonts/OFL-*.txt`) cover Vietnamese. The worker reads them relative to its working directory, so start it from `moonreel-studio`, as `pnpm worker` does.

### Shorts

`planShorts` in `pipeline/jobs.ts` sends the scene list with its timings (measured from the rendered `.srt`) to `buildShortsPrompt`, which picks up to three non-overlapping runs of whole scenes; `normalizeShorts` clamps them to 25–58 s and drops overlaps. Each row in `shorts` then renders on its own job (`renderShortClip` → `renderShort` in `pipeline/shorts.ts`): FFmpeg cuts that span of the final video, and the hook and every caption are drawn by Satori as full-frame PNGs and laid over it with `overlay`, each caption enabled only for its time window (the bundled FFmpeg builds often lack `drawtext`/libass, so text is never drawn by FFmpeg itself). Editing a hook or the scene range cuts the Short again; title and description edits do not.

### Ambient loops

Niches with `format = "ambient"` skip narration: `buildAmbientScriptPrompt` asks for loopable shots of one place, and `projects.audio_path` holds a soundtrack uploaded through `POST /api/uploads/audio` (a route handler outside the proxy, streamed to disk, so large files never pass through a server action). `renderLoop` in `pipeline/render.ts` chains the clips with `xfade`, appends clip 1 again and cuts the result where that copy reaches the first frame, which gives a loop with no seam. Each clip skips its first second (Muse eases in from the still keyframe, so motion there is a third of its later speed) and its last 1.5 seconds (where Muse speeds up), keeps its native 24 fps (converting to 30 repeated every fourth frame), and joins the next one with a 2.5-second smoothstep crossfade. A second FFmpeg pass repeats it with `-stream_loop` and `-c:v copy` up to the soundtrack's length, so only the audio is encoded.

### Why generate a keyframe before the video?
muse2api accepts **one reference image** per request. Feeding the character portrait straight into the video makes the first frame a static portrait. Generating a keyframe first (the character **inside the scene**, at the right aspect ratio) and using it as the video's first frame keeps the character consistent *and* the composition right.

With several characters in a shot, their reference images are laid side by side on one grey sheet (`castReference` in `pipeline/jobs.ts`), and the keyframe prompt names them left to right and tells Muse not to copy the sheet's layout. Characters without a ready reference image are described in words only. With a cast of two or more the narration is always an off-screen voice-over; a lone character still speaks it on screen when the niche has no narrator voice.

### Script rules that avoid known Muse failure modes
- Each scene ≤ 10 s, narration ≤ ~25 words.
- Slow camera, gentle motion: Muse distorts characters in fast action.
- No on-screen text in the image (the app adds subtitles).

### Parsing chat replies
muse2api scrapes the chat answer from the DOM while it streams, so a reply can contain a truncated draft followed by the final JSON. `parseScript` scans every balanced `{…}` block (string-aware) and keeps the last one that validates against the schema.

## 4. Limits and how they are handled

| Limit | Handling |
|---|---|
| muse2api drives one Chromium and is effectively serial | `scene-produce` runs `MUSE_CONCURRENCY` (default 1) jobs at a time |
| 1–3 min per clip; a 6-scene video ≈ 10–20 min | The UI polls progress every 3 s |
| Muse fails or times out occasionally | One in-process retry plus one pg-boss retry; per-scene "Retry" buttons |
| Muse declines a scene (text reply instead of media, usually a content filter) | Stored as a refusal and explained in the UI; **Edit** on the scene card rewrites narration / visuals / camera and requeues it, optionally with a new keyframe |
| A job is redelivered after a worker restart | `produceScene` skips scenes that are already `done` |
| muse.ai cookies expire | muse2api refreshes them; on 401, sign in again on the muse2api admin page |
| Homebrew FFmpeg has no libass | Captions ship as `.srt` + soft subtitles; burn-in is a later phase |

## 5. Risks

- muse2api is an **unofficial** tool that automates a browser session with your cookies. A Meta UI change can break it, and automating a consumer account may violate the terms of service: **use a secondary muse.ai account** while testing.
- Every Muse call goes through `src/lib/providers/`. When Meta ships an official video API, or the project moves to the MCP-connector approach, only a new provider is needed.

## 6. Languages

The UI ships in English and Vietnamese. URLs carry no locale prefix: `src/proxy.ts` picks the locale and rewrites every page request into `app/[lang]/…`.

1. The `moonreel_locale` cookie, set by the EN / VI switch in the sidebar.
2. Otherwise the best match in the browser's `Accept-Language` header (quality values respected).
3. Otherwise English.

Copy lives in `src/i18n/dictionaries/{en,vi}.ts`; `en.ts` is the source of truth and its type forces `vi.ts` to provide every key. Server Components read the locale with `next/root-params` (`getDictionary()` in `src/i18n/server.ts`), Client Components with `useI18n()`, and Server Actions negotiate it from the request like the proxy does (`src/i18n/action.ts`). Because `[lang]` has `generateStaticParams`, both locales are part of the prerendered shell.

The UI language is independent of a niche's **narration language**, which controls what Muse writes.

## 7. Design language

"Frosted champagne glass at midnight": a near-black canvas with a spotlight from above, a faint grid and twinkling stars; surfaces are translucent glass plates lit from behind (inset hairline highlights instead of hard borders); warm cream type; champagne gold used sparingly, with the metallic gradient reserved for the brand, primary actions and active states. Tokens and utilities (`glass`, `frost`, `gold-ring`, `text-luminous`, `sheen`…) live in `src/app/globals.css`; shared components in `src/components/ui.tsx`.
